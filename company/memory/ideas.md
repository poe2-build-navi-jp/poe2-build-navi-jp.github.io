# コンテンツ・施策アイデアのバックログ

2026-09-08時点で `data/builds.json` を実際に検査して見つかった手薄箇所と、
今後の施策候補。優先度は上から順ではなく、着手時にユーザーと相談して選ぶ。

## data/builds.json の手薄箇所（実データ検証済み）

- **評価指標が全ビルドでnull**: `beginnerRating` / `damageRating` /
  `defenseRating` / `mappingRating` / `bossRating` の5項目が、8ビルド全てで
  未設定（null）。評価基準（何を1〜5点等でどう採点するか）の設計自体が
  サイト全体の課題。中途半端な主観評価より、まず採点基準のフォーマットを
  決めてから埋めるべき。
- **sources（裏付け情報源）の件数にばらつき**:
  mercenary(twister-gemling)=1件だったが、2026-09-08にMaxrollのガイド
  （0.5.5対応、WebFetchで内容を直接検証済み）を追加し2件に。
  warrior・huntress・witch=2件、monk・ranger=3件、sorceress・druid=4件は
  未着手。次点の追加対象。
- **ssf（ソロセルフファウンド適性）が半数で未設定**:
  monk, mercenary, huntress, druid の4ビルドで `ssf: null`。
  SSFプレイヤー向けの需要は根強いため、検証して埋める価値がある。
- **levelingStagesの各段階のnowActions等は充実している一方、Endgame以降の
  比較データ（他ビルドとの相対評価、装備の具体的な価格帯・入手難易度）は
  記事内では扱われていない**（要件からの推測。深掘り時に確認）。

## 施策候補（次の一手）

1. 評価指標（5項目）の採点基準を設計し、8ビルド分を埋める。
2. sourcesが手薄なビルド（mercenary最優先、次点でwarrior/huntress/witch）に
   一次情報・検証済み情報源を追加する。
3. ssf未検証の4ビルドについて、SSFでの成立可否を調査・記載する。
4. 既存8ビルドの「比較記事」（例：初心者おすすめ度ランキング、コスト別比較、
   ボス攻略適性比較）を新設し、単体ビルド記事同士を横断的にリンクさせる
   （SEO的な内部リンク強化にもなる）。
5. `_next/static/` の要否をユーザーに確認し、不要なら削除してリポジトリを整理する。
6. PoE2 1.0・基本無料化移行（2026年12月11日予定、伝聞・要一次情報確認）に向けた
   特設コンテンツ（新規プレイヤー向け導線、新クラス情報のプレースホルダー等）の
   準備時期を検討する。ただし一次情報の裏付けが取れてから着手する。

## セッション開始フックとの連動

- `.claude/hooks/session-start-tasks.sh` が上記の「評価指標未設定」「sources不足」
  「ssf未検証」を機械的にスコアリングし、セッション開始時に1件ずつ深掘り候補を
  提示する（`decisions.md` 参照）。このアイデアリストは、その提案を実際の作業に
  落とし込む際の参照先として使う。
