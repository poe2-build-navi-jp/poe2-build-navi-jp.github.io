# note.com記事の作成方針（コンテンツ部＋SEO部門の型を運用ルール化）

`org-chart.md`で確認した「コンテンツ部」「SEO部門」の役割を、note.com記事執筆の
具体的な手順に落とし込んだもの。2026-09-08、ユーザー指示により作成。

## 目的（ここが一番大事）

**noteの記事単体で完結させない。noteで集客し、本サイト（POE2ビルドナビ）へ
誘導する導線を作ることが目的。** そのため、以下を必ず満たす：

- 記事内に本サイトへのリンクを最低1つ、できれば2〜3箇所（記事一覧＋関連する
  個別ページ）入れる。
- 本サイト側には記事の内容を転載・新設しない（ユーザー指示、2026-09-08）。
  noteはあくまで外部の集客チャネルとして独立させる。
- リンク先は「もっと詳しく知りたくなった読者が実際に読みたくなるページ」を選ぶ
  （記事のトップページではなく、話題にした具体的なビルド記事など）。

## 執筆の型：結論→理由→方法→次の行動（コンテンツ部）

1. **結論**：この記事で一番伝えたいことを冒頭で言い切る（見出し＋最初の段落）。
   例：「PoE2が12/11に1.0＆無料化」「モンクのビルドがSSFで成立すると判明」等。
2. **理由**：なぜそれが言えるのか、根拠を示す。一次情報・複数情報源での裏取りを
   明示する（本サイトの編集方針＝断定しない姿勢をnote記事にも適用する）。
3. **方法／中身**：具体的に何を調べた・何がわかったかを、読者が実際に使える
   形で書く（表・箇条書きなど）。
4. **次の行動**：読者に次に何をしてほしいかを明示する＝本サイトへのリンク、
   ブックマーク・フォローの呼びかけ。ここが「導線」の核心。

## SEO・集客の型（SEO部門）

- 書く前に「どんな検索意図・関心を持った人に届けたいか」を一言で決める
  （例：「PoE2を1.0で始めようか迷っている人」「SSFでやりたい人」）。
- タイトルには具体的な固有名詞・数字を入れる（日付、ビルド名、クラス名など）。
  抽象的な煽りタイトルより、検索・SNSでの引っかかりを優先する。
- ニュース性（公式発表・アップデート等）があれば冒頭のフックに使う。ただし
  一次情報での裏取りを済ませてから書く（`rules.md`の出典ルールに従う）。

## 見出し画像（既存ルール、rules.mdと重複記載）

- 記事には必ず見出し画像をセットで作る。PoE2公式アートワークは使わず、
  オリジナルのテキスト／図形デザイン（HTML＋Playwrightスクリーンショット等）。
