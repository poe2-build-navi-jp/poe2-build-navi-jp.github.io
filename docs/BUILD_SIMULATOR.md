# ブラウザ版ビルドシミュレーター

公開パス `/simulator/`。トップ／ビルド一覧から12方針を選ぶか、個別ビルドのボタンから `?build=<掲載ビルドID>` を指定して開く。

## 初期構成と計算の範囲

掲載ガイドの職業・アセンダンシー・主力スキルを設定する。装備、完成パッシブ、推奨サポート構成、予算別完成例を自動で再現したものではない。初期Lv80・ジェムLv1、装備／パッシブなし、キャンペーンのライフ5%報酬なしから利用者が編集する。未装備の武器で主力スキルが成立しない場合はスキルを設定してもダメージが出ない。

PoBRの独立計算エンジンを使用。ゲーム全機構や実戦DPS、相場・売買成立を保証しない。主力スキル1組を選択して計算し、互いに排他的なスキルのDPSを勝手に合算しない。未対応修飾効果、装備の解析エラー、パッシブ診断を表示し、計算失敗時に古い数値を現在の結果として表示しない。

## 操作

- 装備：15部位（武器2、防具／アクセサリ、フラスコ2、チャーム3）。部位に合うユニークを検索して現行バリアントの最小／中間／最大ロールを編集欄へ挿入。英語のゲーム内コピー情報も編集・反映可能。
- スキル：主力組の選択、ジェムの入替、Lv／品質、有効／無効、サポート追加、召喚対象の選択。
- パッシブ：全ノード表示、ドラッグ／拡大縮小、検索によるキーボード操作、職業／アセンダンシーへの移動、接続経路・コストのプレビュー後に反映。三択能力値の変更。取得・解除とポイント上限はエンジンの検証を使う。
- 条件：敵の種類、ライフ報酬、日本語の追加効果、メモ。インポートしたその他の条件は保持して表示。
- 比較：現在の数値を基準にし、変更後の差分を表示。
- 保存：ビルドIDごとのブラウザ内保存。JSONファイルのダウンロード／復元。外部アプリ用コードの読み込み／書き出しは提供しない。

構成・装備テキストは外部サーバーへアップロードしない。ゲームデータも同じサイトから配信する。通常のサイト利用計測は既存GA4の設定を継続。URLにはビルドIDのみを使い、構成や装備内容を入れない。

## 固定したエンジンと出典

- ソース／リリース https://github.com/ackness/pobr/releases/tag/v0.0.46
- PoBR `0.0.46` / JSON schema `19` / game data `0.5.5.5`
- リリースアーカイブSHA-256 `49546f88ef88605a3a9071acbb0e411faf87be57081f6e0af1d1d03e27093e3d`
- 同梱のSHA256SUMSとの一致、manifestのJS／WASM／データの各ハッシュを確認済み。
- MITコードのライセンスを `assets/simulator-engine/v0.0.46/LICENSE.txt` に同梱。ゲームデータの権利はGrinding Gear Gamesに帰属。

JSバインディングは原版を保持。WASMをgzip圧縮し、データgzipとともに512KiBずつ分割。初回の転送量は約9.3MB。ブラウザのWorker内で各パートと結合済みファイルのSHA-256を検証し、展開して初期化する。対応データとschemaを一致確認してから計算する。計算データはシミュレーターを選択した時だけ取得する。

再現コマンド：署名付きという主張はせず、リリースのSHA256SUMSを照合して解凍したディレクトリを `node tools/vendor-simulator-engine.mjs <dir>` に渡す。このスクリプトは通常のサイトビルドには含めず、版の更新は別途レビューする。

## ファイルと生成順

- `tools/generate-simulator.mjs`: 日本語の画面、掲載ビルドの入口、名称辞書と初期設定の生成。
- `assets/simulator.js` / `simulator-model.js`: 画面・保存形式・リクエスト変換。
- `assets/simulator-worker.js`: ハッシュ検証、初期化、エンジンRPC。計算式をフロント側で再実装しない。
- `assets/simulator.css`: 独立したレスポンシブ画面。
- `tools/build-steps.mjs`: 通常の生成順へ組込み。サイトマップにも追加。

`generate-simulator` → `generate-html-sitemap` → `generate-sitemap` → ページschema／既存enhancer → `inject-analytics` → `sync-asset-versions`。ビルドガイドの原典確認日を新しく見せる処理は行わない。

## 検証

`npm run test:simulator`。実際の配信バイナリ／ゲームデータをNode Workerで読み込み、同じブラウザ用Workerを通して検査する。

- 12方針のスキル解決と実計算。
- ライフ+100の入力に対する正確な+100の差。
- 未対応効果と解析できない装備の診断保持。
- 接続したパッシブの取得・解除・ポイント不足拒否。
- 一方向の元データの接続も欠落なく、重複なく描画すること。
- ユニークのロール差、保存ファイルの往復で職業／パッシブ／メモ／数値の保持。
- DOM操作から方針選択、装備反映、ジェムLv変更、パッシブの取得、比較用効果、JSON保存、ビルド間の保存隔離と復元。

NodeでのDOM操作検査と実ブラウザの見た目の検査は区別して報告する。

DOMの挙動検査でも実際の全4,913ノードを使用する。非表示タブではSVGを生成せず、通常の表示範囲では470ノードのみ生成されること、縮小時には座標を持つ全ノードが表示されることを検査する。計算とパッシブ操作は実エンジンを使用し、全ノード接続の欠落・重複は別の全データ検査で確認する。サイト全体のSEO・ローカルリンク・既存ビルドのLv入力の検査も通過。

## 日本語表示

`data/simulator-localization.json` はPoE2DBの日本語・英語データをノードIDと名称で照合した表示用データ。現行の4,913ノード、1,073ジェム、435ユニーク、開発用の `[DNT]` 項目を除く召喚対象の名称を確認。パッシブ説明は現行ツリーで日本語を表示する。検索は日本語名と内部の英語名の両方に対応する。

装備欄では名称・既知の効果文を日本語に変換し、計算に渡すときは元の英語形式へ戻す。計算用のスキルID・装備データ・保存形式は維持する。日本語表示から元データへの往復と435種のユニーク原文の保持をテストする。自由入力された未対応の修飾効果は自動翻訳しない。

## 描画と計算の負荷対策

パッシブはタブを開いたときだけ表示範囲内のSVGを生成し、移動では範囲を出入りした要素だけを追加・削除する。取得状態の変更では変更ノードと接続線だけを更新する。ドラッグ・ズーム・リサイズの描画はアニメーションフレーム単位にまとめる。ツリーの解析結果とジェム候補文字列を再利用し、ジェムの全候補は選択欄を開くときに展開する。

再計算は同時に1件だけ実行し、待ち中の変更は最新の1件へ置き換える。計算待ちでは結果欄の高さを維持し、待機表示と比較ボタンの無効化で以前の値と区別する。メモの端末保存は250msにまとめ、ページ非表示時にも保存する。

テストは全ツリーの表示範囲制御、縮小時の座標を持つ全ノード表示、ジェム候補の展開・選択保持、連続10変更で最大2回の計算と最終結果の反映、保存復元を確認する。端末上のフレームレートを測った値ではない。

## レア装備の編集

部位を押すと一覧から編集画面へ切り替え、選んだ部位へフォーカスを移す。「装備の部位一覧へ」で戻る。ユニーク・レア作成・貼り付けを切り替えられる。

`data/simulator-equipment.json` に実エンジンのベース装備と日本語辞書を照合した331ベース、35種類の効果を収録。レア装備ではベース・名前・アイテムレベル・品質・効果と数値を編集し、英語の計算用アイテムテキストへ変換する。反映後はライフ・耐性・DPS等と、編集画面を開いた時点との差分を表示する。レアの編集内容は保存データの `equipmentDrafts` に保持し、計算リクエストの形式は変更しない。

比較用の仮装備であり、実ゲームの付与可否・ティア上限は検証しない。入力は10行まで。暗黙効果・ソケット効果は自動追加せず、必要ならオプションで指定する。フラスコ・チャームのレア作成は非対応。

実WASMで全35効果の解析、ベース防御、ライフ・火耐性・筋力の差分、数値の不正入力、部位との適合、保存の往復を検査。DOM検査で一覧と編集の往復、レアの作成・再反映・再編集、ユーティリティ部位での無効化も確認する。

## パッシブ能力の確認と反映

全4,913ノードに説明を表示する。日本語の能力文は改行を個別効果に分解し、開始点・中央マーク・ジュエルソケットには役割と対応範囲を表示する。元データに効果定義がないノータブルは能力を推測せず、詳細と計算診断で未対応を表示する。能力値ノードは筋力・器用さ・知性の選択に応じた+5を表示・計算する。

スマホのタップはノード周囲20pxの最寄りを選択し、ドラッグと区別する。選択後は能力詳細へフォーカスとスクロールを移す。全能力一覧は30件ずつ表示し、日本語の効果検索・取得済み・種類別フィルターに対応する。SVGのタイトルにも能力を含め、全ノードのDOMを同時生成しない。

経路確認は実エンジンの取得・解除結果から計算用構成を作り、追加・解除される全ノードの能力とステータスの差分を表示する。反映時にはその構成を使い、武器セット別割当を保持する。編集中に構成や選択が変わった場合は古いプレビューを破棄する。通常ノードとアセンダンシーの選択数を分けて表示する。

実WASMで通常ノードのアーマー+10／回避+8、任意能力値+5、カオスイノキュレーションの最大ライフ1を検査。DOMで地図からの選択とフォーカス、一覧ページ送り・種類絞込み、取得前の数値比較、取得・解除・再取得を確認した。実機での見た目は未確認。

## 計算条件の日本語入力

追加効果は日本語候補35種から挿入し、「最大ライフ +100」「火耐性 +30%」「追加物理ダメージ 10〜20」の形式で入力できる。反映前に計算用の英語形式へ変換し、復元時は日本語に戻す。全角数字・記号も正規化する。認識できない日本語は行番号付きのエラーを表示して既存の条件を保持する。既存の英語形式は引き続き保存・計算でき、未対応の自由入力効果は診断欄に表示する。全35形式の往復、ライフの実計算、日本語候補の追加、保存後の表示復元、不正入力時の変更拒否を検査する。

## 1枚のツリー上のテンプレート

画像比較・参照URL・手動目標のUIを撤去し、12ビルドそれぞれ5段階の参考ルートを `data/simulator-routes.json` に定義する。このサイト独自の育成目安であり、NINJAの完成ツリーのコピーではない。現行ゲームデータの実在するノードを指定し、同じ職業の開始点から接続した経路を生成する。キーストーン、他職業の開始点、アセンダンシー、中央マークは自動で経由しない。装備・ステータス条件に応じた完成形の保証ではない。

`node tools/generate-simulator-routes.mjs` で同梱データから再生成可能。全12ルートの全段階の接続・実在性・通常ポイント79以内・選択職業との一致と、実エンジンの解除プレビューを検査する。

テンプレートは水色の線と淡い静止光、実際の取得済みは金色で同じSVGへ描画する。参考ルートは計算リクエストへ渡さない。表示・非表示、段階変更、ルート全体への移動、次の未取得ノードの選択で、保存した計算構成とライフが変わらないことをDOMテストで確認する。取得は従来どおり経路・変化を確認して明示的に反映する。参考段階の表示設定だけをビルド別に保存する。

スマホでは画像・比較枠を排除して1枚の地図を幅いっぱいに表示し、高さは画面に合わせ400〜620pxで確保する。参考の残ポイントと次のノードへのボタンを近くに置く。SVGの表示範囲絞り込みを保ち、点滅・アニメーションや追加の全ツリー描画は行わない。

## ツリー操作中のページ移動対策

地図内だけ `touch-action: none` と非passiveのtouch開始・移動抑止を適用し、ページのスクロールやiOSのゴムバンド動作への引き渡しを防ぐ。地図外のスクロールは抑止しない。ドラッグは開始したpointerIdだけを追跡し、6pxのしきい値を超えてから地図を動かす。終了座標も判定するため移動イベントを受け損ねてもノード選択にならない。キャンセル・capture喪失で状態を解放する。

地図からのノード選択は詳細を更新するだけでフォーカス／ページスクロールを移さない。検索・次の目標など明示的な移動操作では従来の詳細案内を保持する。ツリーパネルのscroll anchoringと文字選択を抑止する。DOMテストでドラッグによるviewBox移動、選択されないこと、スクロール関数が呼ばれないこと、別ポインターとキャンセルの扱い、地図内だけtouchが抑止されることを検査。iPhone実機では未検証。

## 地図だけのピンチズーム

2本のPointer Eventsを追跡し、指の間隔と中央位置からSVGのviewBoxだけを変更する。指を広げると拡大、近づけると縮小し、指の中央が示すツリー座標を保持する。1本へ戻ると現在の位置からドラッグを再開し、ピンチ終了時にノードを誤選択しない。キャンセル・capture喪失とblurで操作状態を解除する。Safariのgestureイベントも地図内だけ抑止し、ページのviewport設定は変更しない。ホイールもカーソル位置を基準にツリーだけを拡縮する。既存の800〜60000のviewBox幅制限と表示範囲描画を維持する。

DOMで非primaryの2本目の指、拡大・縮小と中央位置、1本指への復帰、キャンセル、ページスクロール呼び出しゼロ、viewportと計算構成が変わらないことを検査。iPhone実機では未検証。

## スマホのツリー専用画面

スマホではパッシブタブの選択から、PCでは「ツリーだけを大きく編集」から、ツリー専用の全画面パネルを開く。検索・テンプレート設定は折り畳み、地図へ広い領域を確保する。ノードをタップすると画面内の能力パネルが開き、そこで経路確認と反映を行える。ピンチ・ドラッグは地図の表示だけを変える。

取得・解除の反映は同じ計算構成へ即時保存し、全画面内にも現在のライフ・アーマー・回避力・DPSと保存／計算状態を表示する。「保存して戻る」は最終構成の再計算完了を待ち、保存を確認してから元の画面へ戻る。処理中の追加操作を防ぐ。端末保存ができない場合は成功と扱わずファイル保存の案内を表示する。キーボードのフォーカスを画面内に保持し、閉じるとページのスクロール設定とフォーカスを戻す。

DOMで全画面を開き、パッシブを実計算へ反映した直後に閉じても、保存データに割当が残り、戻った画面のアーマーが+10増加することを検査する。iPhone実機でのレイアウト確認は未実施。

## 取得済み0の表示と武器スロット

職業・アセンダンシーの開始点を取得済みとは別の状態と色で描画する。開始点は取得数・取得済みフィルターに含めず、実際の取得ノードだけを金色にする。参考ルートは引き続き計算に含めない。新規構成は取得済み0、既存の構成は保存した取得内容を復元する。「取得済み0から選び直す」で全割当・能力値選択・武器セット別専用割当をクリアでき、直前の状態へ戻すこともできる。

装備欄に武器スロット1・2の切替を追加し、それぞれにメイン武器とサブ武器・盾、レア編集内容を保存する。計算用itemsへは現在のセットの武器だけを入れ、非選択セットは保存メタデータ `weaponSets` に保持する。JSON保存にも含める。既存形式の武器はセット1として移行する。既存の武器セット専用パッシブがある場合は、切替先の割当に追従する。

実WASMでセット1のライフ+100、セット2の+200が合算されず切り替わることを確認。DOMで初期取得済み0と開始点の別表示、取得・全解除・戻す際のアーマー変化、武器セット間のライフ差とレア編集内容・JSON保存・ビルド切替後の復元を検査する。
