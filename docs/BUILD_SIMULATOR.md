# ブラウザ版ビルドシミュレーター

公開パス `/simulator/`。トップ／ビルド一覧から12方針を選ぶか、個別ビルドのボタンから `?build=<掲載ビルドID>` を指定して開く。

## 初期構成と計算の範囲

掲載ガイドの職業・アセンダンシー・主力スキルを設定する。装備、完成パッシブ、推奨サポート構成、予算別完成例を自動で再現したものではない。初期Lv80・ジェムLv1、装備／パッシブなし、キャンペーンのライフ5%報酬なしから利用者が編集する。未装備の武器で主力スキルが成立しない場合はスキルを設定してもダメージが出ない。

PoBRの独立計算エンジンを使用。ゲーム全機構や実戦DPS、相場・売買成立を保証しない。主力スキル1組を選択して計算し、互いに排他的なスキルのDPSを勝手に合算しない。未対応修飾効果、装備の解析エラー、パッシブ診断を表示し、計算失敗時に古い数値を現在の結果として表示しない。

## 操作

- 装備：15部位（武器2、防具／アクセサリ、フラスコ2、チャーム3）。部位に合うユニークを検索して現行バリアントの最小／中間／最大ロールを編集欄へ挿入。英語のゲーム内コピー情報も編集・反映可能。
- スキル：主力組の選択、ジェムの入替、Lv／品質、有効／無効、サポート追加、召喚対象の選択。
- パッシブ：全ノード表示、ドラッグ／拡大縮小、検索によるキーボード操作、職業／アセンダンシーへの移動、接続経路・コストのプレビュー後に反映。三択能力値の変更。取得・解除とポイント上限はエンジンの検証を使う。
- 条件：敵の種類、ライフ報酬、英語の追加修飾効果、メモ。インポートしたその他の条件は保持して表示。
- 比較：現在の数値を基準にし、変更後の差分を表示。
- 保存：ビルドIDごとのブラウザ内保存。JSONファイルのダウンロード／復元。外部アプリ用コードの読み込み／書き出しは提供しない。

構成・装備テキストは外部サーバーへアップロードしない。ゲームデータも同じサイトから配信する。通常のサイト利用計測は既存GA4の設定を継続。URLにはビルドIDのみを使い、構成や装備内容を入れない。

## 固定したエンジンと出典

- ソース／リリース https://github.com/ackness/pobr/releases/tag/v0.0.46
- PoBR `0.0.46` / JSON schema `19` / game data `0.5.5.5`
- リリースアーカイブSHA-256 `49546f88ef88605a3a9071acbb0e411faf87be57081f6e0af1d1d03e27093e3d`
- 同梱のSHA256SUMSとの一致、manifestのJS／WASM／データの各ハッシュを確認済み。
- MITコードのライセンスを `assets/simulator-engine/v0.0.46/LICENSE.txt` に同梱。ゲームデータの権利はGrinding Gear Gamesに帰属。

JSバインディングは原版を保持。WASMをgzip圧縮し、データgzipとともに512KiBずつ分割。初回の転送量は約9.3MB。ブラウザのWorker内で各パートと結合済みファイルのSHA-256を検証し、展開して初期化する。対応データとschemaを一致確認してから計算する。計算データはシミュレーターを選択した時だけ取得する。

再現コマンド：署名付きという主張はせず、リリースのSHA256SUMSを照合して解凍したディレクトリを `node tools/vendor-simulator-engine.mjs <dir>` に渡す。このスクリプトは通常のサイトビルドには含めず、版の更新は別途レビューする。

## ファイルと生成順

- `tools/generate-simulator.mjs`: 日本語の画面、掲載ビルドの入口、名称辞書と初期設定の生成。
- `assets/simulator.js` / `simulator-model.js`: 画面・保存形式・リクエスト変換。
- `assets/simulator-worker.js`: ハッシュ検証、初期化、エンジンRPC。計算式をフロント側で再実装しない。
- `assets/simulator.css`: 独立したレスポンシブ画面。
- `tools/build-steps.mjs`: 通常の生成順へ組込み。サイトマップにも追加。

`generate-simulator` → `generate-html-sitemap` → `generate-sitemap` → ページschema／既存enhancer → `inject-analytics` → `sync-asset-versions`。ビルドガイドの原典確認日を新しく見せる処理は行わない。

## 検証

`npm run test:simulator`。実際の配信バイナリ／ゲームデータをNode Workerで読み込み、同じブラウザ用Workerを通して検査する。

- 12方針のスキル解決と実計算。
- ライフ+100の入力に対する正確な+100の差。
- 未対応効果と解析できない装備の診断保持。
- 接続したパッシブの取得・解除・ポイント不足拒否。
- 一方向の元データの接続も欠落なく、重複なく描画すること。
- ユニークのロール差、保存ファイルの往復で職業／パッシブ／メモ／数値の保持。
- DOM操作から方針選択、装備反映、ジェムLv変更、パッシブの取得、比較用効果、コード書出し、ビルド間の保存隔離と復元。

NodeでのDOM操作検査と実ブラウザの見た目の検査は区別して報告する。

DOMの挙動検査ではJSDOMのSVG処理負荷を抑えるため、マップ表示だけを小さなノード集合に絞る。計算とパッシブ操作は実エンジンを使用し、全ノード接続の欠落・重複は別の全データ検査で確認する。サイト全体のSEO・ローカルリンク・既存ビルドのLv入力の検査も通過。
