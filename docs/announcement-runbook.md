# 公式発表の日にやること（ExileCon・1.0パッチノート）

社内メモ（`docs/` は公開対象外）。計画全体は `docs/launch-1-0-plan.md`。

## 共通ルール
- 載せるのは**公式の告知ページ・トレーラー・パッチノート・公式配信**で確認できたことだけ。予想・リーク・配信者の感想は載せない。
- 数値・名称は原文どおり。日本語名が未発表のものは英語名のまま書き、「日本語名は未確認」と添える。
- 「確定事項」と「ビルドへの影響」を先に公開し、細部は後から追記してよい。追記したら確認日（`checkedAt`）を更新する。
- 1回のPRは小さく。作業前に `git fetch origin main` で最新を取り込む（Codexなど他の作業と衝突しやすい）。

## ExileCon当日（基調講演：日本時間11月7日（土）午前6時〜、約2時間）
1. 基調講演の後、公式の告知ページ（pathofexile.com のニュース・フォーラム、Steamの公式ニュース）を開き、発表項目を一覧にする。
2. `data/seo-pages.json` の `/poe2-1-0/exilecon-2026/` を更新する（このファイルは手で整形されているため、該当オブジェクトだけを書き換える）。
   - `answer`：発表の要点を2〜3文に差し替える。
   - 「発表される内容」セクション：見出しを「発表された内容」に変え、確認できた項目を箇条書きにする（各項目の末尾に出典の告知ページ名）。
   - `sources`：使った公式告知ページを追加する。
   - `faq`：「ExileCon 2026では何が発表された？」に答えを入れる。
3. 影響のあるページを更新する：Duelist（`/poe2-1-0/duelist/`）、公開予定日（`/poe2-1-0/release-date/`）、1.0ハブ（`tools/generate-discovery-pages.mjs` の ExileCon セクション）。
4. 掲載ビルドに影響しそうな発表は、1.0のビルド対応状況ページの該当ビルドに「影響あり（確認待ち）」と書く。
5. `npm run build`、全テスト、PR、マージ、公開サイトで確認。

## 1.0パッチノート公開日
1. 公式パッチノートを読み、`docs/templates/patch-notes-summary.json` をコピーして `【】` の部分を埋める。
2. 完成したオブジェクトを `data/seo-pages.json` の `/poe2-1-0/exilecon-2026/` の後ろに追加する。
3. 1.0ハブと公開予定日ページから、パッチノート要約へリンクする。
4. 掲載12ビルドについて、パッチノートで主力スキル・サポート・アセンダンシーの変更を探し、「掲載ビルドへの影響」表に書く。判断できないものは「要確認」とする。
5. `npm run build`、全テスト、PR、マージ、公開サイトで確認。Search Consoleで新ページのインデックス登録をリクエスト（運営者）。
