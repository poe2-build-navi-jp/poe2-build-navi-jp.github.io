# 装備選びと比較の操作フロー（2026-11-12）

1. 装備編集の「比較候補に追加して比較」で、未反映の装備を入れた名前付き構成と予定額を保存。現在の装備・自動保存は変更しない。必要能力値は比較結果で確認する。保存上限・別タブ更新・未保存の予定額・無効な数値・装備の読み込み失敗を検出する。構成一覧と予定額の片方だけ保存に失敗したら、今回の書き込みだけを戻す。
2. 幅720px以下ではDPS・ライフ・火冷雷耐性と、構成を開いた時（または指定基準）からの差を固定表示。再計算中は古い値を出さず、各指標から内訳へ移動できる。パッシブ全画面編集では既存の表示と重ならない。下部余白とsafe-areaを確保する。
3. 比較表の下に装備・ジェム・パッシブ・能力値選択・主力指定などの変更を表示する。装備テキストはエスケープし、長い一覧・テキストは省略を明示する。共通の敵条件と装備効果を混同しない。
4. A/B比較URLは2つの構成・共通の敵・予定額と予算をフラグメントに持つ。構成名とメモを含めず、上限24000文字。受信側では一時的な構成として比較し、既存の自動保存・名前付き保存・予定額を書き換えない。編集で古い共有結果を無効にする。
5. 指輪・靴の2本の記事に、同じWASMで生成した固定入力・数値表・短い再現用リンクを掲載。価格は操作用の仮入力で、相場や装備の実在・付与可否を示さない。記事、検索一覧、シミュレーターから進める。

実装の検証は `npm run test:simulator`、記事・検索・サイトの日付とリンクは既存回帰テストを使う。候補保存の途中失敗・非同期計算中の編集・共有受信の保存分離・メモ除外・不正URL・コピー権限がない場合も検証する。記事の数値は実WASMの再計算と一致することを確認する。

通常のサイト生成のOG描画は、この実行環境のChromiumソケット制限で起動できない。今回のOG画像は既存画像を再利用する構成で、画像ファイル自体は変更していない。HTML生成・メタデータ付与は完了。実ブラウザで記事からの再現、共有URL、幅390px・高さ844pxのフレームで装備候補保存と固定バーを確認済み。スクリーンショットは `qa/simulator-mobile-candidate.jpg`。
